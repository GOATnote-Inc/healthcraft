# Native HealthCraft arm: offline controls

These are scripted-provider controls around the actual HealthCraft
`run_agent_task` loop and real roster tools. No model inference or network access
occurred in these six control attempts. Each case retains its scheduled
denominator of one, raw fake-provider exchanges, actual tool captures,
completion, mechanical certificate, cleanup and source/runtime identities.

`native_arm.py` is the exact temporary harness used locally; its absolute
checkout path records that environment and is not a portable installation
default. It requires an explicit fake or live command-line mode. These artifacts
do not authorize a live run. `fake-test-report.json` records the six passing
controls and rejection of an existing output directory. Truncation, round-limit,
timeout and digest-mismatch cases retain unsuccessful outcomes.

`fake-wire-comparison.json` compares the successful native control with the
parent directory's corrected Gym control. Initial native request objects match.
Later tool result JSON has equal parsed values but different framework-native
whitespace. Both serializations are preserved; this is not all-turn byte parity.

All historical clinical criteria remain unassessed. Compatibility trajectory
score fields are ungraded placeholders, explicitly marked in metadata. No
clinical, training or performance superiority conclusion follows from these
engineering controls. Live model output is deliberately absent from this folder.

`manifest.json` hashes the promoted files. Copies are byte-identical to the
temporary evidence; captures are parsed JSON envelopes, not network attestations.
